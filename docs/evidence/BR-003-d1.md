# BR-003 — Sites D1 binding and migration workflow

Status: local evidence captured; saved Sites-version verification is pending.

## Implementation

- `.openai/hosting.json` continues to use the existing project and declares the
  logical D1 binding as `"d1": "DB"`; no Site or binding was created here.
- `db/index.ts` keeps D1 access behind `getD1()` and exposes the read-only
  `readD1Health()` helper.
- `app/api/health/d1/route.ts` serves `GET /api/health/d1`. It runs `SELECT 1`
  and checks only SQLite's catalog for the base migration table. It does not
  read application records, identity headers, cookies, or secrets, and returns
  `Cache-Control: no-store, private`.
- `db/schema.ts` defines the neutral `runtime_metadata` table used as the base
  migration marker. Product tables are intentionally deferred to later tasks.
- `drizzle/0000_careless_colossus.sql` is the generated, reviewable D1
  migration. Regenerate it with `npm run db:generate` after schema changes.
